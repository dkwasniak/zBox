## Current Audio Architecture (Reference)

[Verified in current code: `esp32/src/audio.cpp`]

- Internal queue `audioQueue` (FreeRTOS, capacity 5) holds `AudioCmd` structs.
- Commands: `PLAY / STOP / PAUSE / RESUME / VOLUME`.
- Queue-full: command silently dropped with `LOGW`. **This is insufficient for the new contract.**
- Feedback: global volatile flags `isPlaying`, `isPaused`, `trackEndedFlag`.
- No correlation between issued command and feedback event.
- BT state: polled via `audioPollBtConnection()`, not callback-driven.

The new audio adapter must replace this with deterministic feedback. The existing internal
queue can remain, but the public interface must change.

## New Audio Adapter Contract

### Public Interface

```cpp
// All functions return immediately. Feedback arrives via Event queue.
// cmd_id is generated by the dispatcher before calling these functions.

bool audioAdapterStartNfcPlayback(const char* uid, CmdId cmd_id);
    // Resolves uid → file path using figurineMap.
    // Returns false if mapping not found (synchronous failure — no queue needed).
    // On false: dispatcher posts NfcPlaybackStartFailed(uid, MappingNotFound, cmd_id) itself.
    // On true: adapter posts NfcPlaybackStarted or NfcPlaybackStartFailed asynchronously.

bool audioAdapterStartMusicTrack(uint16_t index, CmdId cmd_id);
    // Resolves index → file path from music library.
    // Returns false if index out of range (synchronous failure).
    // On true: posts MusicTrackStarted or MusicTrackStartFailed asynchronously.

void audioAdapterStop(CmdId cmd_id);
    // Prioritized to front of queue.
    // Posts AudioStopped(cmd_id) when stop is confirmed by audio task.
    // StopAudio supersedes any pending play/start commands (see Supersession Rule).

void audioAdapterPause(CmdId cmd_id);
void audioAdapterResume(CmdId cmd_id);
    // Post AudioStopped or failure events on completion.

bool audioAdapterPlaySystemSound(uint8_t sound_id, CmdId cmd_id);
    // Resolves sound_id → file path via systemSoundMap.
    // Returns false if mapping not found.
    // On true: posts SystemSoundCompleted or SystemSoundFailed asynchronously.
    // TrackEnded is NOT emitted for system sounds — only SystemSoundCompleted/Failed.
```

### Feedback Events Posted by Audio Adapter

All feedback events are posted to the central event queue via `postEventFromTask()`.

| Event | Trigger | Carries |
|-------|---------|---------|
| `NfcPlaybackStarted` | File opened and audio pipeline running | uid, cmd_id |
| `NfcPlaybackStartFailed` | File open failed or queue rejected | uid, reason, cmd_id |
| `MusicTrackStarted` | File opened and playing | index, cmd_id |
| `MusicTrackStartFailed` | File open failed or queue rejected | index, reason, cmd_id |
| `AudioStopped` | Stop command processed by audio task | cmd_id |
| `SystemSoundCompleted` | System sound file finished playing | sound_id, cmd_id |
| `SystemSoundFailed` | File not found or playback timeout | sound_id, reason, cmd_id |
| `TrackEnded` | Natural EOF of main track (not stop, not pause) | — |
| `AudioCommandRejected` | Queue full (see Queue Full rule) | cmd_id, reason |

Rules:
- `TrackEnded` is emitted ONLY for natural completion of a `StartNfcPlayback` or
  `StartMusicTrack` command. System sounds use `SystemSoundCompleted` instead.
- `StopAudio` never causes `TrackEnded` — it causes `AudioStopped`.
- `Pause` never causes `TrackEnded`.
- Queue full is NOT silent: posts `AudioCommandRejected(cmd_id, AudioCommandRejected)`.

## Command Correlation (CmdId Mechanism)

See also [02_events_effects.md §CmdId](02_events_effects.md).

The audio adapter stores the `cmd_id` alongside each queued command:

```cpp
struct AudioCmd {
    AudioCmdType type;      // PLAY / STOP / PAUSE / RESUME / VOLUME / SYSTEM_SOUND
    char path[128];         // resolved file path (or empty for non-file commands)
    uint8_t sound_id;       // for SYSTEM_SOUND commands
    uint8_t volume_percent; // for VOLUME commands
    CmdId cmd_id;           // correlation ID from dispatcher
};
```

The audio task includes `cmd_id` in every feedback event it posts. The dispatcher uses
`cmd_id` to:
1. Identify which pending effect the feedback corresponds to.
2. Cancel the timeout associated with that effect.
3. If the feedback is a failure, decide whether to retry or propagate to reducer.

---

## Supersession Rule

`StopAudio` supersedes pending play commands:

When `StopAudio(cmd_id_stop)` is dispatched while a `StartNfcPlayback(cmd_id_play)` is
in flight:
1. Audio adapter flushes pending PLAY commands from the queue.
2. Audio adapter posts `AudioCommandRejected(cmd_id_play, AudioCommandRejected)`.
3. Audio adapter posts `AudioStopped(cmd_id_stop)` when stop is confirmed.

Implementation: `xQueueSendToFront` ensures STOP is processed before pending PLAY.
After STOP is dequeued, the audio task drains and discards remaining PLAY commands
with their `cmd_id`s, posting `AudioCommandRejected` for each.

## Timeout Ownership

Timeouts are owned by the dispatcher, not the audio adapter.

| Command | Timeout | On expiry |
|---------|---------|-----------|
| `StartNfcPlayback` | 5000ms (AUDIO_START_TIMEOUT_MS) | Post `NfcPlaybackStartFailed(AudioStartTimeout)` |
| `StartMusicTrack` | 5000ms | Post `MusicTrackStartFailed(AudioStartTimeout)` |
| `StopAudio` | 2000ms | Post `AudioStopped` with warning (best effort) |
| `PlaySystemSound` | 30000ms (sound duration bound) | Post `SystemSoundFailed(PlaybackTimeout)` |

Dispatcher manages one `PendingEffect` record per outstanding CmdId:

```cpp
struct PendingEffect {
    CmdId cmd_id;
    EffectType type;
    uint32_t timeout_deadline_ms;  // 0 = no timeout
};
```

When `timeout_deadline_ms != 0 && millis() >= timeout_deadline_ms`, dispatcher posts the
synthetic failure event and removes the pending record.

---

## Idempotency Rule

- Calling `StopAudio` when audio is already stopped: adapter posts `AudioStopped` immediately.
- Calling `StartNfcPlayback` when audio is playing: adapter stops current track, starts new one.
  Posts `NfcPlaybackStarted` for the new track; old track's `TrackEnded` is suppressed.
- Calling `PauseAudio` when already paused: no-op, no event posted.

---

## Queue Full Rule

If the internal audio queue is full when a command arrives:
- Adapter posts `AudioCommandRejected(cmd_id, AudioCommandRejected)` immediately.
- This is NOT a silent drop. The dispatcher receives the rejection and passes it to the reducer.
- Reducer decides: retry (if queue depth was transient), or transition to error state.

Current queue depth: 5 commands. [Must validate in implementation: measure worst-case
burst depth under combined button + NFC + BT events.]

## BT Connection Events

BT connection state changes are NOT handled by the audio adapter in the new model.
They are handled by the BT adapter (see [05_bt_nfc_adapters.md](05_bt_nfc_adapters.md)).
The audio adapter exposes only audio-path commands and feedback.
